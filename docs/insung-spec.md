# 인성질 랭킹 (`/insung`) 기능 명세 v0.3

> v0.3에서 점수 규칙이 **포인트 예산제**로 바뀌었다. 점수·투표·삭제·데이터·API에 관해서는 **12장이 3·5·7·8장보다 우선**한다.

친구들의 "인성질"을 **제보**로 등록하고, 친구들이 공감 투표(👍)로 점수를 매겨 누가 인성질을 제일 잘하는지 집계한다.
인성질은 카톡 메시지, 직접 나눈 대화, 행동 등 **무엇이든** 될 수 있으며 유형을 나누지 않는다. 제보 본문은 발언이면 그대로 옮겨 적고, 행동이면 무슨 일이 있었는지 서술한다.
카톡 메시지는 복사해서 붙여넣으면 편하지만, 이것은 입력 방법 중 하나일 뿐이다.

### 용어

| 용어 | 뜻 | 코드상 이름 (변경 없음) |
|---|---|---|
| 제보 | 인성질 한 건 (발언·행동 구분 없음) | `InsungQuote`, `/api/insung/quotes` |
| 주인공 | 인성질을 한 사람 | `author` |
| 등록자 | 제보를 올린 사람 | `registrant` |

이미 운영 데이터가 있을 수 있어 컬렉션·API·필드 이름은 바꾸지 않고, 화면 문구만 바꾼다.

## 1. 범위

- 경로: 페이지 `/insung`, API `/api/insung/*`
- 루트 메뉴([src/app/page.tsx](../src/app/page.tsx))의 `games` 배열에 항목 추가 (이름 예: "인성질 랭킹")
- 사용자: 기존 5명 고정 — `VALID_PLAYERS` (`잡/큐/지/머/웅`, 표시명은 `playerNames.ts`)
- 저장소: 기존 MongoDB(mongoose). 컬렉션 3개 추가
- 랭킹 기간: 전체 누적만 (주간/월간은 v0.1 범위 밖)

## 2. 인증 (PIN)

| 항목 | 규칙 |
|---|---|
| 신원 | 5명 중 한 명으로 고정. 이름 선택 + 본인 PIN으로 인증 |
| PIN 설정 | 처음 접속할 때 본인이 설정(숫자 4자리). 서버에는 해시(`crypto.scrypt` + salt)만 저장 |
| 선점 방지 | 이미 PIN이 있는 이름은 PIN 입력만 가능. 아직 PIN이 없는 이름만 설정할 수 있음 |
| PIN 리셋 | 관리자 비밀번호(`RECORD_SUBMISSION_OVERRIDE_PASSWORD`)로 특정 사용자의 PIN 삭제 → 그 사람이 다시 설정 |
| 세션 | 인증에 성공하면 httpOnly·Secure·SameSite=Lax 서명 쿠키 발급(HMAC, 180일). 서명 키는 신규 env `INSUNG_SESSION_SECRET` |
| 세션 무효화 | 쿠키에 `pinVersion`을 넣어 둠. PIN을 리셋하거나 바꾸면 version이 올라가서 기존 쿠키는 무효 |
| 무차별 대입 방지 | 사용자별로 PIN을 5회 연속 틀리면 10분 잠금 (실패 횟수와 잠금 시각은 DB에 저장) |
| API 신원 | 쓰기 API는 모두 **쿠키로만** 사용자를 확인. body로 받은 voter/registrant 값은 무시 |
| 로그아웃 | 쿠키 삭제 (다른 이름으로 바꾸고 싶을 때) |

## 3. 점수 규칙

- **점수 = 해당 사람이 주인공인 제보들이 받은 투표 수의 합.** 발언이든 행동이든 1표 = 1점으로 동일
- 제보를 등록하면 = 등록자가 그 제보에 투표 1개 (자동). 등록자도 이후 투표를 취소할 수 있음
- 같은 제보에는 한 사람이 1표만 가능 (`UNIQUE(quoteId, voter)`)
- **본인이 주인공인 제보에는 투표할 수 없음.** 본인이 등록한 경우(자수)에도 자동 투표 없이 0점에서 시작
- 투표를 취소하면 -1. 0표가 된 제보도 목록에는 남음

## 4. 제보 등록

1. 본문 입력: 무슨 말·행동을 했는지 적는다
   - 카톡 메시지라면 [붙여넣기] 버튼(`navigator.clipboard.readText`)으로 복사한 내용을 바로 넣을 수 있음
   - 대화는 들은 말을 옮겨 적고, 행동은 상황을 서술 (예: "약속 30분 늦고 사과 한마디 없음")
2. 주인공 버튼(5명) 탭 → 저장

| 필드 | 필수 | 규칙 |
|---|---|---|
| content (본문) | O | trim 후 1~500자. 발언 인용 또는 행동 서술 |
| author (주인공) | O | `VALID_PLAYERS` |
| context (상황 메모) | X | 최대 100자 |
| saidAt (발생 날짜) | X | 기본값 오늘(KST), 미래 날짜 불가 |
| registrant | 자동 | 세션 사용자 |

**중복 병합**: 공백을 정규화(연속 공백·개행을 공백 1개로, trim)한 본문과 주인공이 기존 제보와 같으면 새 제보를 만들지 않는다. 유형을 나누지 않으므로 모든 제보에 같은 규칙을 적용한다. 행동 서술은 사람마다 다르게 쓰기 때문에 정확히 일치하는 경우는 드물고, 비슷한 중복은 등록자 삭제나 관리자 삭제로 정리한다.
- 아직 투표하지 않았고 본인이 주인공이 아니면 → 기존 제보에 투표하고 "이미 등록된 제보라 투표로 반영했어요" 안내
- 이미 투표했거나 본인이 주인공이면 → "이미 등록된 제보예요" 안내
- `normalizedContent + author` 조합에 unique 인덱스를 둬서 동시 등록 경쟁도 막음

## 5. 수정·삭제·취소

| 동작 | 권한 |
|---|---|
| 투표 취소 | 투표한 본인 (👍 다시 누르면 토글) |
| 제보 수정 | **등록자 본인만.** 본문·주인공·상황 메모·발생 날짜를 바꿀 수 있음. 받은 포인트·투표는 그대로 (주인공을 바꾸면 점수도 새 주인공에게 이동) |
| 수정 중복 | 다른 제보와 주인공 + 정규화 본문이 같아지면 409 |
| 제보 삭제 | 등록자 본인, 또는 관리자 비밀번호 입력 |
| 제보 삭제 시 | 그 제보의 투표도 함께 삭제 (점수에서 빠짐) |

## 6. 화면 (`/insung` 한 페이지, 탭 또는 섹션)

- **상단**: 로그인 상태("재웅으로 접속 중 · 로그아웃"), 제보 등록 폼
- **랭킹**: 순위 · 이름 · 점수 · 제보 수. 동점이면 같은 순위로 표시하고 다음 순위는 건너뜀(카탄과 같은 경쟁 순위). 이름을 누르면 그 사람의 제보 목록
- **최신 피드**: 최신순 제보 카드 — 본문, 주인공, 상황 메모, 발생일, 👍 수, 투표한 사람 이름, 내 투표 여부(토글 버튼), 삭제 버튼(권한이 있을 때만)
  - 발언과 행동을 구분하지 않으므로 본문에 인용부호(“ ”)를 자동으로 붙이지 않고, 입력한 그대로 표시
- **레전드 TOP**: 투표가 많은 순 상위 10개 (동률이면 먼저 등록된 제보가 위)
- **사람별 모아보기**: 주인공으로 필터한 피드 (투표순/최신순 정렬)
- 유형 필터나 아이콘 구분은 두지 않음
- 로그인하지 않은 상태: 조회만 가능하고, 등록·투표 시 이름/PIN 입력 모달을 띄움

## 7. 데이터 모델 (mongoose)

```ts
InsungUser   { player: PlayerCode (unique), pinHash, pinSalt, pinVersion,
               failedAttempts, lockedUntil?, createdAt }
InsungQuote  { content, normalizedContent, author: PlayerCode, context?, saidAt?,
               registrant: PlayerCode, voteCount, createdAt }
               index: unique(normalizedContent, author), (author), (voteCount, createdAt)
InsungVote   { quoteId, voter: PlayerCode, createdAt }
               index: unique(quoteId, voter)
```

`voteCount`는 비정규화 카운터로, 투표·취소할 때 `$inc`로 갱신한다. 랭킹은 `InsungQuote`를 author 기준으로 aggregate해서 voteCount 합과 제보 수를 계산한다. v0.2에서 스키마 변경은 없다.

## 12. v0.3 포인트 예산제

1표 = 1점이면 가벼운 인성질과 레전드가 똑같이 1점이다. 차등을 주기 위해 **매월 받는 포인트를 나눠서 투표**한다. 포인트가 한정돼 있으니 진짜 레전드에 포인트가 몰리게 된다.
투표 자체에는 잠금이나 본인 금지 같은 제약을 두지 않고, **예산만으로** 조절한다.

### 12.1 규칙

| 항목 | 규칙 |
|---|---|
| 지급 | 매월 1일 0시(KST) 기준으로 1인당 **50포인트** (v0.3 배포 직후 20 → 50으로 상향: 기존 투표 차감으로 잔액이 음수인 사용자가 생겨서) |
| 투표 | 한 제보에 **1~5포인트** 중 골라서 투표. 1인 1제보 1회 |
| 잔액 부족 | 남은 포인트보다 큰 점수로는 투표 불가 |
| 등록 시 투표 | 등록자가 **0~5포인트** 중 선택 (기본 1). 0이면 투표 없이 등록 → 0표 제보 가능 |
| 본인 제보 | 내가 주인공인 제보에도 투표 가능 (자수도 포인트를 줄 수 있음) |
| 이월 | 쓰지 않은 포인트는 **상한 없이 전부** 다음 달로 이월 (음수 잔액은 이월하지 않음) |
| 취소 | **언제 한 투표든** 취소 가능. 포인트는 그 투표를 했던 달로 돌아감 (지난달이면 이월을 통해 반영) |
| 점수 변경 | 이번 달 투표면 차액만 차감·환불. 지난달(또는 포인트제 이전) 투표면 **이번 달 투표로 옮겨** 새 점수 전부를 이번 달 예산에서 차감 |
| 지난 제보 | 등록 시기와 관계없이 투표 가능. 이번 달 포인트로 차감 |
| 제보 점수 | 받은 포인트 합 (`pointTotal`) |
| 랭킹 점수 | 주인공별 `pointTotal` 합. 동점 처리는 기존 경쟁 순위 그대로 |
| 레전드 TOP | `pointTotal` 내림차순 (동률이면 먼저 등록된 제보가 위) |

지급량·점수 범위·시작 월은 `src/constants/insungPoints.ts` 상수로 조정한다.

### 12.2 잔액 계산

잔액은 따로 저장하지 않고 투표 기록에서 계산한다.

```
지급(월)   = 50
이월(월)   = max(0, 잔액(전월))      // 시작 월은 0
사용(월)   = 그 달(KST)에 속한 내 투표 points 합
잔액(월)   = 지급 + 이월(월) - 사용(월)
```

- 시작 월은 `2026-11`. 시작 월부터 이번 달까지 차례로 계산한다 (5명·월 단위라 계산량은 무시할 수준)
- **기존 투표 처리:** 포인트제 이전 투표(`month` 없음)는 1포인트로 점수에 반영하고, **시작 월 사용량으로 차감**한다. 예) 기존에 6번 투표했다면 11월 잔액은 50 - 6 = 44
- 기존 투표가 50개를 넘으면 시작 월 잔액이 음수가 될 수 있다. 이때는 투표를 취소해 잔액을 만들기 전까지 새 투표를 할 수 없고, 다음 달 이월은 0으로 계산한다

### 12.3 제보 삭제

- 제보와 그 제보의 투표를 실제로 삭제한다. 그 제보에 준 포인트는 투표했던 달로 모두 돌아간다

### 12.4 데이터 변경

```ts
InsungVote   + points?: number (1~5, 기존 문서는 없으면 1로 간주)
             + month?: string ('YYYY-MM', KST. 예산 집계용. 기존 문서는 없으면 시작 월로 간주)
             index: (voter, month)
InsungQuote  + pointTotal?: number (비정규화. 없으면 voteCount로 간주)
             // voteCount는 득표 수 표시용으로 유지
```

- **마이그레이션 없음.** 값이 없으면 `$ifNull`로 기본값을 읽는다
- 투표가 바뀔 때마다 그 제보의 `voteCount`·`pointTotal`을 투표 기록에서 다시 계산한다
- 동시 요청 방어: 로컬 MongoDB(standalone)는 트랜잭션을 못 쓰므로, **저장 후 잔액을 다시 계산해 음수면 되돌린다** (투표 삭제·점수 원복, 등록이면 제보도 삭제). 병렬 7건(5포인트씩, 잔액 30)에서 6건만 저장되는 것을 확인

### 12.5 API 변경

| Method | Path | 변경 |
|---|---|---|
| GET | `/api/insung/budget` | **신규.** 내 이번 달 지급·이월·사용·잔액. 로그인 안 했으면 `null` |
| POST | `/api/insung/quotes` | body에 `points`(0~5, 기본 1) 추가. 0이면 투표 없이 등록. 중복 병합 시에도 같은 포인트로 투표 (0이면 `duplicate`) |
| POST | `/api/insung/quotes/[id]/vote` | body `{points: 1~5}`. 투표 안 했으면 투표, 했으면 점수 변경. 결과 `created`/`changed`/`unchanged`. 잔액 부족 409 `insufficient_points` |
| DELETE | `/api/insung/quotes/[id]/vote` | 언제 한 투표든 취소 |
| DELETE | `/api/insung/quotes/[id]` | 제보와 투표 삭제, 포인트 환불 |
| GET | `/api/insung/quotes`, `/leaderboard` | `pointTotal` 기준 정렬·합산. 제보 응답에 `pointTotal`, `voters[{player, points}]`, `myPoints` 포함 |

v0.2의 "본인이 주인공인 제보 투표 불가(403)"와 "자수는 0점 시작" 규칙은 없어졌다.

### 12.6 화면 변경

- 상단(로그인 상태 옆): **이번 달 남은 포인트** 표시 (예: `🔥 43 / 60 (+10 이월)`)
- 등록 폼: 포인트 선택 0~5 (기본 1). 잔액보다 큰 값은 비활성
- 제보 카드: 👍 버튼 대신 포인트 선택 1~5. 내가 준 점수 강조, 같은 점수를 다시 누르면 취소
- 카드 점수: `🔥 12 · 4명`처럼 포인트 합과 득표 수를 함께 표시. 투표자 목록은 `채림 5 · 순규 3`처럼 점수와 함께
- 랭킹 점수 = 포인트 합. 사람별 모아보기 정렬은 최신순/포인트순

### 12.7 확정 사항

- 이월 상한 없음, 포인트제 시작 월 `2026-11`
- 기존 투표는 1포인트씩 시작 월 할당량에서 차감
- 투표 잠금·본인 투표 금지 없음, 0표 등록 허용

## 13. 제보 수정 (v0.3.1)

- 내가 등록한 제보 카드에만 **수정** 버튼이 보이고, 누르면 카드 안에서 바로 편집한다 (본문·주인공·상황 메모·발생 날짜)
- 삭제 버튼은 모든 카드에 보인다. 내 제보는 확인 후 바로 삭제, 남의 제보는 관리자 비밀번호를 입력해야 삭제

## 14. 탭 구성 (v0.3.2)

- 탭 순서: **랭킹 → TOP10 → 최신 → 내 투표** (레전드 TOP는 TOP10으로 이름 변경)
- **내 투표**: 내가 포인트를 준 제보만 모아 본다. 로그인해야 볼 수 있고, 로그인 전에는 로그인 안내를 보여준다
- API: `GET /api/insung/quotes?voted=me` → 세션 사용자가 투표한 제보만 반환. 로그인 안 했으면 401
- 화면의 이모지는 외곽선 아이콘(`src/components/Icon.tsx`)으로 바꿨다 (붙여넣기·왕관·점수 별·닫기)
- 사람별 모아보기와 내 투표의 정렬은 **포인트순(기본) → 최신순** 순서로 둔다

## 15. 투표 부하 방어 (v0.3.3)

별을 1→5→3처럼 연타해 DB 부하를 일으키는 것을 막는다. 새 인프라 없이 세 단계로 막는다.

| 단계 | 내용 |
|---|---|
| 화면 연타 묶기 | 별을 누르면 화면(점수·투표자·잔액)은 바로 바뀌고, 서버 요청은 마지막으로 누른 뒤 0.6초가 지나면 **마지막 값 한 번만** 보낸다. 처음 점수로 돌아왔으면 요청하지 않는다. 실패하면 원래 상태로 되돌린다 |
| 요청당 작업 줄이기 | 투표 API는 먼저 저장하고 잔액을 **한 번만** 계산한다 (음수면 되돌림). 응답에 바뀐 제보와 잔액을 담아, 화면이 목록·잔액·랭킹을 다시 부르지 않는다. 랭킹은 랭킹 탭으로 돌아올 때 갱신 |
| 서버 요청 수 제한 | 투표·등록·수정·삭제를 사용자별로 **1분에 30회**까지 허용. 넘으면 429 `rate_limited` + `Retry-After`. 서버리스 인스턴스끼리 공유되도록 MongoDB `InsungRateLimit` 문서(고정 윈도우, `$inc`)에 센다. 오래된 문서는 TTL로 1시간 뒤 삭제 |

- 제한 값은 `src/constants/insungPoints.ts`의 `INSUNG_WRITE_LIMIT_PER_WINDOW`, `INSUNG_WRITE_LIMIT_WINDOW_SECONDS`로 조정한다
- 투표 API 응답: `POST/DELETE /api/insung/quotes/[id]/vote` → `{ status?, quote, budget }`
- 필요해지면 요청 수 제한만 Upstash Redis(`@upstash/ratelimit`)로 옮길 수 있다
